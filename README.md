# StoryCut

StoryCut 是一款 Windows AI 解说剪辑工具，用于把较长的视频整理为 3 分钟以内、适合 YouTube Shorts 发布的英文解说成片。

仓库只维护 StoryCut 一个应用。当前已完成“理解原片 → 组织故事 → 匹配镜头 → 预览导出”的完整流程，支持语音视频、纯画面视频、长片分层理解、故事保真与自动拆分、文案审查、GPT-SoVITS 外部配音、字幕样式、成片质量检查和安全更新。

```text
storycut_v2/    StoryCut 应用代码（内部目录名为兼容旧项目路径而保留）
models/         共用 Faster-Whisper 模型，不提交
venv/           Python 虚拟环境，不提交
.env            API 地址与密钥，不提交
export/         用户可见的统一导出目录，不提交
requirements.txt
```

## 安装

在仓库根目录创建虚拟环境并一次安装全部依赖：

```powershell
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
```

根目录 `requirements.txt` 已引用 StoryCut 的依赖清单，不需要重复安装子目录清单。

还需要安装 FFmpeg 和 ffprobe，可加入系统 PATH，也可在应用配置中指定绝对路径。Faster-Whisper 模型位置和自动下载方式参见 [MODEL_DOWNLOAD.md](MODEL_DOWNLOAD.md)。首次理解原片时如缺少配置模型，程序默认显示下载进度，完成后自动继续；也可在 `storycut_v2/config.user.yaml` 中关闭自动下载：

```yaml
analysis:
  auto_download_model: false
```

## 启动

双击根目录中的：

```text
点我启动StoryCut（AI解说剪辑）.vbs
```

启动器使用 `pythonw.exe`，正常运行时不会显示 CMD 窗口。也可在根目录运行：

```powershell
venv\Scripts\python.exe storycut_v2/main.py
```

程序启动后会在后台静默检查更新；发现新版时，首页更新按钮会显示绿色可更新标识，不会自动弹窗打断操作。

## 功能说明

### 1. 理解原片

- 使用 FFmpeg/ffprobe 读取视频信息、生成封面、检测场景并提取关键帧。
- “语音与画面”使用本地 Faster-Whisper 转写中文语音，再用关键画面补充上下文。
- “纯画面叙事”跳过语音转写，分析人物动作、姿态、工具交互、环境、障碍、变化和场景衔接。
- 默认自动执行分层理解：短视频跳过冗余综合调用，长视频分片分析后建立全片章节、关键事实、转折和跨场景联系；失败时自动回退基础理解。
- 视觉请求同时识别清晰可见的文字、表格、图表趋势、图示关系和公式；看不清的内容不会猜测。
- 重要但不确定的技术画面可抽取高清原帧复查，默认最多 6 个，没有需要复查的内容时不增加请求。
- 处理过程默认显示动态状态；只有取得持续且稳定的实测速度后才显示预计剩余时间。

### 2. 组织故事

- “语音与画面”把原片内容压缩为自然的英文科普解说，保留关键机制、因果、证据、转折和结论。
- “纯画面叙事”先通读全片事件生成故事规划，再由最终故事编辑模型写成具有环境、动作、动机和情绪线索的英文解说。
- 支持自动叙事策略，也可手动指定；“不设置”保持基础故事逻辑。
- 支持 60、90、120、180 秒目标，单集硬上限为 179 秒，为 Shorts 三分钟限制留出余量。
- 英文解说可直接编辑并自动保存；参考 SRT 按 GPT-SoVITS 标点规则拆句。
- 旁白时长综合英文单词、音节、标点停顿和历史真实配音语速估算；导入同步 SRT 后始终以真实配音时间为准。
- 可选“文案审查”一次检查事实、原片证据、因果、数字单位和术语一致性；应用建议后重建 SRT，并在已有时间线时自动重匹配镜头。
- 长片故事保真与自动拆分使用多信号触发检查，包括时长、事件数、中译英容量、持续语音密度、有效信息点、技术证据、关键事实/转折和单集时长压力。只有一条三分钟视频确实讲不完整时，才拆成最少数量的独立分集。

### 3. 匹配镜头

- 根据事件绑定、字幕、视觉描述、时间顺序和重复使用情况，从全部场景中自动匹配镜头。
- 每句解说保留多个候选；正常流程无需逐句手选。
- 候选替换和 0.5 秒入点/出点调整位于“高级调整”。
- 镜头不足时可组合多个场景，时间线会随项目保存。
- 自动拆分后的每个分集拥有独立故事和镜头时间线，仍沿用同一套匹配流程。

### 4. 配音、字幕与预览导出

- 导出 GPT-SoVITS 使用的英文参考 SRT，再导入生成的英文音频和同步 SRT。
- 缺少同步 SRT 时，可按需用共享 Faster-Whisper 模型重新识别英文配音。
- 真实配音超出 179 秒时，先在最高 1.25x 范围内安全加速；仍超限时按本次真实语速生成精简方案。
- 应用精简前自动归档旧故事、配音和同步字幕，恢复时先并排对比，再由用户确认。
- 没有 TTS 环境时，可生成无声音或保留原声的“仅字幕测试预览”。
- 默认移除原片声音；“保留原片声音”是可选项。
- 默认保持原视频分辨率和宽高比，不缩放、不补边、不裁切。
- 使用 ASS 烧录英文字幕，支持字体、字号、边距、颜色、描边、阴影、粗体、斜体、字间距和字幕动画。
- 内置标准字幕、清爽描边、Shorts 大字、纪录片暖白、科普黄字、极简白字预设。
- 字幕底板同时承担衬托英文字幕和遮挡原字幕的作用，支持黑色遮罩、局部模糊和 Delogo。
- 预览区支持方向锁定拖动、中心/边缘吸附、滑块和精确数值输入，也可生成 FFmpeg 真实效果预览。
- 成片检查会检查项目完整性、时长、镜头覆盖、空隙、重叠、越界、闪切、重复使用、字幕时间线、黑画面、静音、异常音量、编码和音轨。
- FFmpeg 完成后再使用 ffprobe 验证真实输出，诊断命令和滤镜保存到根目录 `export/_internal/`。

## API 与模型配置

首页“API 设置”可管理共享 `.env` 中的 `OPENAI_API_KEY` 和 `OPENAI_BASE_URL`，无需手动寻找配置文件。接口地址应填写 OpenAI 兼容 API 根地址，通常以 `/v1` 结尾，不要填写服务商网页或完整的 `/chat/completions` 地址。

界面可分别选择故事生成、最终故事编辑和视觉理解模型。“选择模型”会异步读取兼容接口的 `/models` 列表；接口不支持列表时仍可手动输入。纯画面模式可让经济型视觉模型承担批量理解，让更强的文本模型负责全片故事编辑。

## 本地数据与项目结构

以下内容受 Git 忽略和内置更新器保护，不会提交或被版本更新覆盖：

- `.env`
- `models/`
- `venv/`
- `storycut_v2/config.user.yaml`
- `storycut_v2/projects/`
- `storycut_v2/cache/`
- `export/`
- `.update_backups/`

每个 StoryCut 项目主要包含：

```text
analysis/     转写、场景、关键帧、事件和分层结构
script/       故事规划、英文解说、审查结果和参考 SRT
timeline/     镜头匹配和粗剪时间线
audio/        英文配音、同步字幕及原始导入备份
archive/      改稿、精简或恢复前的可恢复版本
cache/        封面与项目预览缓存
project.json  项目状态、项目名和字幕设置
```

用户需要查找的成品统一位于根目录 `export/`，并使用项目名作为文件名前缀。

## 更新方式

StoryCut 启动后会静默检查 GitHub 版本。有新版时，用户确认后：

1. 正常 Git 克隆、位于 `main` 分支且受跟踪程序文件没有本地修改时，后台执行快进更新。
2. 没有 Git、不是克隆目录或 Git 更新不可用时，自动使用 ZIP 清单同步。

两种方式都不会执行 `git clean`、`reset --hard`、强制重置或删除未知文件。ZIP 更新会先把将要变更的程序文件备份到 `.update_backups/`，并保护本地项目、配置、模型和导出文件。

## 当前边界

- GPT-SoVITS 暂不内嵌，继续使用“导出参考 SRT → 外部生成 → 导入配音和同步 SRT”的流程。
- Delogo 使用传统 FFmpeg 周边像素插值，复杂动态背景可能出现拉伸纹理。
- 当前以单项目人工确认流程为主，尚未支持批量任务。
- 自动竖屏裁切和主体跟踪不属于默认行为。

### 3.0：从文稿开始

创建项目时增加“从视频开始”和“从文稿开始”两个入口。文稿项目保持四步：

1. **整理文稿**：粘贴或导入文稿，整理英文解说、目标时长和可选事实审查。
2. **规划分镜**：为每个旁白单元生成镜头用途、理想画面、必须内容、可接受替代、避用内容和搜索关键词；显示预计镜头段数、建议素材文件数和覆盖率。
3. **匹配素材**：支持本地素材文件夹、场景检测、缩略图、标签、全局自动匹配、镜头锁定和绿/黄/红置信状态；找不到准确素材时提示应补充什么画面。
4. **配音与导出**：复用 GPT-SoVITS、同步 SRT、字幕样式、成片检查和导出；真实配音导入后按实际时间再次调整镜头。

实施顺序：

1. 先完成纯文稿项目、本地素材导入、分镜列表、素材数量提示、自动匹配和缺失镜头提示。
2. 再接入 Pexels、Pixabay 等具有正式 API 的免费素材来源，并保存作者、原始链接、素材 ID、下载日期和许可记录。
3. 后续按需增加本地视觉语义匹配、低置信度镜头 AI 复核，以及波形、地图、图表和知识卡等本地图形模板。
