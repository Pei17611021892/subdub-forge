# 当前阶段：从纯文稿生成视频

## 目标与版本定义

在现有 StoryCut 中新增“从纯文稿开始”的稳定创作方式：用户提供文稿，程序规划英文解说与分镜，分析用户素材或免费素材，自动匹配镜头，最后复用已有配音、字幕、画布、成片检查和导出能力生成 Shorts。

这条流程达到可用闭环后，从开发预览转为正式功能，但不使用 `3.0.0` 作为完成标志。StoryCut 继续沿用当前版本序列小步发布：`2.1.1` 之后依次使用 `2.1.2`、`2.1.3` 等版本；原有视频流程始终作为核心入口长期维护。

## 已完成

- 创建项目支持“从视频开始”和“从文稿开始”。
- 文稿可粘贴或从文件导入，原稿保存到项目并自动保存编辑。
- AI 将文稿整理为英文旁白和逐段分镜需求，记录理想画面、必须内容、可接受替代、避用内容及英文搜索词。
- 展示分镜段数、建议素材数量、覆盖状态和待补素材提示。
- 超出 Shorts 容量的纯文稿结果可以组织成多个独立部分，避免规划阶段直接失败。
- 支持导入本地视频或图片素材。
- 支持配置 Pexels/Pixabay 官方 API，按分镜搜索、预览候选、记录来源并下载到项目。
- 免费素材搜索在后台运行并显示进度；网络失败不会破坏已有项目数据。
- 本地导入和已下载素材统一写入可恢复清单，使用稳定 ID 保存来源、作者、许可页、文件状态、时长和分辨率；缺失文件不会阻止项目打开。
- 素材分析在后台增量执行：视频使用 FFmpeg 场景检测，图片作为静态候选，代表缩略图、基础标签和分析状态持久化，已完成文件可复用缓存。
- 分镜按全部候选做全局分配，优先避免无意义重复；结果包含高/中/低置信状态、匹配原因、替代候选和补素材提示。
- 用户替换候选后自动锁定，也可单独切换锁定状态；重新匹配保留锁定结果。
- 候选支持双击调用系统默认播放器或看图程序打开原素材；候选卡片宽度受主内容区约束，不会被素材分辨率撑宽页面。
- `matches.json` 和 `rough_cut.json` 已记录具体素材路径、媒体类型、场景 ID 与入点/出点，真实配音重定时不会丢失多素材来源。
- 成片渲染器已支持同一时间线混合多个视频文件与静态图片；视频按场景入出点裁剪，图片按解说时长循环输入，再统一应用画布、字幕和英文配音。
- 纯文稿项目的成片检查改为逐项校验时间线素材，不再要求单一原视频；缺失素材、时间线空隙、时长不足和 Shorts 超限仍会阻止输出。

## 当前缺口

素材分析、自动匹配、候选原素材预览和多素材导出链路第一版已经接通，并通过视频、图片、配音、字幕和竖屏画布的真实 FFmpeg 合成验证。当前仍缺用户真实项目的完整操作验证和置信阈值校准，因此纯文稿流程继续保持开发预览状态。

## 当前实施顺序

### 1. 素材入库与恢复

- 统一扫描本地导入和已下载素材。
- 为每个文件记录稳定 ID、路径、来源、作者、许可证页面、媒体类型、时长、分辨率和文件状态。
- 项目关闭重开后完整恢复；文件缺失时标记，不让界面卡死。

### 2. 素材场景分析

- 视频使用 FFmpeg 场景检测切分为候选镜头，避免把整段素材当作一个镜头。
- 为候选镜头生成代表缩略图，图片素材直接作为一个静态候选。
- 保存场景起止时间、时长、缩略图及分析状态，支持中断后继续。
- 优先本地处理；不要默认对每帧调用视觉 API。

### 3. 标签与语义描述

- 先利用文件名、来源搜索词、下载时对应分镜和已有元数据生成基础标签。
- 需要画面理解时按代表帧批量处理，控制请求数量。
- 标签至少覆盖主体、动作、环境、景别、方向、情绪/氛围和不适用条件。
- 不确定内容明确标注，不得根据模糊画面编造事实。

### 4. 全局自动匹配

- 同时考虑分镜必须内容、可接受替代、避用内容、搜索词、镜头时长和标签相似度。
- 进行全局分配，而不是每句独立贪心选择；控制完全重复镜头和素材过度集中。
- 没有准确素材时选择当前最合理替代，同时明确提示理想补充画面。
- 输出绿/黄/红置信状态、匹配原因和多个替代候选。
- 用户可以锁定镜头；重新匹配不得覆盖锁定结果。

### 5. 时间线与导出闭环

- 将选中素材的具体入点/出点写入统一时间线。
- 按旁白或真实同步 SRT 调整镜头长度，必要时组合多个短镜头。
- 图片素材应支持安全的静态持续时间，后续可再考虑轻微推拉效果。
- 复用 2.x 已完成的 GPT-SoVITS、同步 SRT、字幕、画布、成片检查和根 `export/` 导出能力。

## 交互要求

- 普通用户看到的是“导入/寻找素材 → 自动分析 → 自动匹配 → 只处理低置信项”，不要暴露大量技术参数。
- 所有耗时分析均在后台运行，提供明确进度和阶段状态；关闭程序不会丢失已完成数据。
- 分镜列表需要显示当前镜头、候选缩略图、置信状态、来源和“这里更适合什么画面”的提示。
- 用户替换或锁定镜头后立即持久化。

## 成本与版权原则

- 优先使用本地 FFmpeg、文本标签和已有搜索元数据，视觉 API 只用于信息不足或低置信候选。
- 不自动抓取没有正式 API 或许可信息不清晰的网站。
- Pexels/Pixabay 素材保留来源、作者和页面链接；最终是否满足发布用途仍提示用户确认。

## 正式可用验收标准

- 一个新纯文稿项目能从原稿完成分镜规划、素材准备、素材分析、自动匹配、配音/SRT 导入、预览检查和最终导出。
- 项目重启后所有阶段状态、素材、镜头选择和锁定状态均能恢复。
- 素材不足不会直接失败：能提供替代镜头和明确的补素材说明。
- 自动匹配结果可编辑，并且不会在重新匹配时覆盖用户锁定项。
- 最终视频满足现有 Shorts 时长限制并通过成片质量检查。
- 视频入口的既有流程与项目兼容性不受影响。
- 新功能具备服务层测试、控制器恢复测试、QML 加载测试和至少一次真实素材闭环验证。

## 本阶段暂不扩展

- 直接内嵌 GPT-SoVITS。
- 无许可来源的网页抓取。
- 批量生成多个项目。
- 全自动 AI 视频生成。
- 高成本逐帧视觉理解。
